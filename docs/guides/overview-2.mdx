Deploying the hook is not so complex as it might seem to be: 

## 1. Clone the repository

Clone the [Pulse Hook repository](https://github.com/no-hive/pulse_hook) and move into the project directory:

```bash
git clone https://github.com/no-hive/pulse_hook.git
cd pulse_hook
```

The repository is structured as a monorepo. It contains not only the hook itself, but also the project's documentation and dedicated instructions for LLMs and AI agents. This makes it easier for an agent to access the relevant project context, documentation, and development instructions when you work with the project through an AI coding agent.

## 2. Install dependencies

Install all project dependencies using Forge:

```bash
forge install
```

This installs the dependencies for the entire repository.

## 3. Compile and test

Before deploying, make sure everything compiles and all tests pass:

```bash
forge build
forge test
```

**If both commands complete successfully, you're ready to configure the deployment.**

If something goes wrong, first make sure the repository and all dependencies were downloaded successfully. Try running `forge install` again, then run `forge clean` followed by `forge build` and `forge test`. If the problem persists, check the error message and open an issue with the relevant logs.

## 4. Configure environment variables

Start by copying the example environment file and filling in the required values:

```bash
cp .env.example .env
```

At minimum, you will need:

- `MAINNET_RPC_URL` — RPC endpoint for the network you want to deploy to.
- `PRIVATE_KEY` — private key of the wallet that will deploy the hook.
- `WALLET_ADDRESS` — address of the deploying wallet.

Make sure your `.env` file is not committed to the repository.

## 5. Deploy

Run the deployment script with Forge:

```bash
forge script script/00_DeployHook.s.sol:DeployHookScript \
  --rpc-url $MAINNET_RPC_URL \
  --private-key $PRIVATE_KEY \
  --sender $WALLET_ADDRESS \
  --broadcast
```

### Chain configuration

You **do not need to manually specify the chain ID or deployment configuration**.

`HelpConfig` automatically detects the chain ID from the network you are deploying to and selects the appropriate deployment arguments for that chain.

In other words, the same deployment command can be used across supported networks. Just point `MAINNET_RPC_URL` to the network you want to deploy to — `HelpConfig` will handle the rest.

> **Important:** Make sure your RPC URL points to the intended network before running the command. The deployment configuration is selected automatically based on the detected chain ID.

That's it — Forge will broadcast the deployment transaction to the selected network.

## 6. Verify the hook deployment

After the deployment, check that the hook has been deployed with the expected permissions.

Find the **deployed hook address** in the Forge deployment logs. This is the address of the hook contract that was created by the deployment script. 

You can add it to .env as \$DEPLOYED\_HOOK\_ADDRESS and then run:

```bash
cast call \
  "$DEPLOYED_HOOK_ADDRESS" \
  "getHookPermissions()(bool,bool,bool,bool,bool,bool,bool,bool,bool,bool,bool,bool,bool,bool)" \
  --rpc-url "$MAINNET_RPC_URL"
```

The command will return the hook's configured permissions. Compare them with the permissions expected for your hook to make sure the deployment configuration is correct.

> **Note:** The hook address is the address of your deployed hook contract, **not** the Uniswap Pool Manager address.
